Three stages, each one auditable on its own

the reasoning gets smarter without the action space getting less bounded
1DETECT

Every at-risk event, typed

Failed payments, abandoned checkouts, and overdue invoices — each one carries its own signal (error code, abandon reason, days overdue) into the next stage.

2DIAGNOSE

Why the money is stuck

A real LLM call reads the failure text and picks a root cause with a one-sentence reason — falling back to a deterministic rule table on any API failure, never silently.

real LLM call rule-based fallback
3DECIDE + ACT

One bounded action, logged first

A small fixed action set — retry, nudge, human handoff, or write-off — chosen and logged before the outcome is known, so the trail can't be accused of rationalizing after the fact.
